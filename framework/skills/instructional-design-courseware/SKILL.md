# 课件设计（逆向设计 + 学习科学）

## 铁律
1. **先定「学完能做什么」，再定「怎么证明做到了」，最后才排活动。** 顺序颠倒就会写出"热闹但学不到东西"的课。
2. **每一节必须有一句可检验的目标**（动词可观察：能讲出、能画、能对比、能推翻一处说法）。禁用「了解」「感受」「培养兴趣」这类不可检验的说法作为唯一目标。
3. **活动 = 练习的一部分，不是表演。** 每节课至少一次「学生自己动手产出 + 有人当场反馈」。
4. **跨材料口径必须一处定义、处处一致**：课时数、总时长、排期、价格、模块编号、术语表。改任何一项，反查所有对外材料（海报/大纲/报名页/文案）。
5. **不编造事实**：学校名、师资、升学结果、合作方、数据都不能凭空写；缺就留空并标注待确认。
6. **写目标前先查教材口径**：这个概念在本学段教材里第几年级出现、用什么词，按教材的用词与难度写，别让孩子觉得课上一个说法、学校一个说法。教材库、来源与目录抽取见 `references/textbook-reference-library.md`。
7. **只改语言时不动结构**：用户要求"改文案/改语言"时，模块数、课时、顺序、样题、结课标准全部原样，交付时明写"结构一个没动"——他就是在这层起疑。
8. **模块标题必须同轴且互斥**。混轴是"像拼凑"的唯一根因：把「抽象/逻辑」（能力名词）和「选题/研究/成文/讲述」（流程动词）排在一条序列里，读者一眼就觉得不是一套东西。**一条轴只放同一类词**——六个能力名词（抽象/逻辑/批判/系统/论证/表达），或六个流程阶段，不混用。流程词降级成项目里程碑，在每节课的后半段出现，不进标题。
9. **贯穿全课的大课题必须每节都在场**。曾把「AI for Math/Art/History」压成"从五道样题里选一道"，结果三样东西一起丢：学科身份、每科方法差异、贯穿性。改法：大课题＝固定的分组身份 × 每节都要往前推进一步；同一节能力训练里，各组用**同一套方法、各自的题目**（抽象课全班都画结构图，Math 组画证明结构、History 组画史料来源结构）。
10. **设计类需求先提问再动笔**。用户原话：「你可以通过向我提问，跟我沟通来逐渐完善，不用你自己瞎编」。架构层面的分歧（主轴选哪个、大课题怎么组织、载体是什么、线上线下怎么分工、能否重命名）**先用结构化问答收口，再出文档**；拿不准就列方案让他挑，而不是自己定一版再说。
11. **线上课必须绑定平台的具体功能，并且每 8–10 分钟换一次动作。** 只说"互动一下"等于没设计：要写到"用会议软件的哪个功能、孩子做什么、几秒内能出结果"（投票扣字母、白板拖卡、聊天区接龙、分组讨论、共享屏幕挑错）。纯口播超过 5 分钟，线上注意力就掉了。配方见 `references/hook-and-interaction-design.md`。
12. **开篇用"孩子愿意猜"的问题，不用抽象概念。** 有效结构是「一个反直觉的问题 + 3–4 个选项 + 每个选项都能落到真实现象」——揭晓时那句"四个都对了一半"本身就是最好的教学时刻，比直接给定义有用。把抽象能力写在最后一段让他自己推出来。
13. **线下动手＝用 AI 去拆东西，不是用 AI 做东西。** 让 AI 当被拆解的对象或对手盘（猜内部结构→动手拆→找 AI 猜错的地方；同题多问看温度；给矛盾资料看它顺着谁说），孩子当解构的人。只让孩子"打开 AI 聊两句"或"用 AI 做个小作品"，两小时就白花了。
14. **你自己必须带领域输入，不能只镜像用户的大纲。** 用户原话：「你是不是要有自己的输入啊，不是光看我怎么说」。用户给的顺序只是骨架，每一节的能力必须由你补齐「这个能力由哪几个机制构成」并**给机制起名字**（有名字才可被检验、被引用）。只把用户的话排版成表＝没干活。常用骨架：抽象思维五机制、功能抽象（sense–think–act）、学习科学检查项——见 `references/abstraction-thinking.md`。
15. **目标描述必须"说人话"，教研黑话会被当场打回。** 「把自己学科的问题画成结构图，说清简化了什么、丢了什么」被用户直接回「我听不懂你在说啥呢」。合格写法：一个家长听得懂、老师能当面验证的动作句——「能把自己那道题拆成几块、画成一张图，并说清这张图省掉了什么」。避开：结构图、简化了什么、思维工具、能力矩阵、迁移度。每个模块目标写完自问一句：没上过课的人能听懂吗？能拿这句话问孩子吗？（黑话→说人话的替换表在 `chinese-edu-copy`）

## 线上为主时的交付机制（线下只剩一两次时必加）
课时从"线上+线下对半"改成"线上为主"时，最容易塌的四件事：讲太多、没人真动手、掉线跟不上、家长看不见。四条机制写进每节教案：
- **固定五段式**：5′ 复述上次（检索练习，不许翻笔记）→ 15′ 只讲一个新概念 → 25′ 当场动手（屏幕共享报进度）→ 10′ 提交小物 + 随机抽 3 人三问 → 5′ 预告。
- **每次必交一个"小物"**（可截图/可粘贴），没有小物＝这次课没发生；提交率低于 80% 不推进新模块。
- **双人互检 + 随机口述**（你做了什么／AI 做了什么／你质疑过什么）。作品可以由 AI 生成，追问不行——这是防"学了工具就飘"的主力。
- **课后 24h 内给家长一条**：今天学了什么、孩子拿出什么、今晚可以问他一个什么问题。
- **异步兜底包**（8 分钟录屏 + 一页任务单）：掉线、请假、设备问题都能补。
- **线上做低门槛高认知，线下做高门槛动手**：线上适合分类、概念图、测谎、核验、写要求单；线下留给拆设备、搭助手、当众讲。线下只剩两次时，压在"看真实世界"和"当众受压"这两件线上做不出来的事上。

## 知识地图 / 提问链（讲原理类章节的通用做法）
不先抛术语，用一串提问让孩子自己走到概念上；再上一张概念地图把"谁依赖谁、谁是谁的上一层"讲清。要点：
- 每个台阶＝「一个具体问题 → 一个可立住的概念」，孩子先说、老师只归纳；最后一阶收在"为什么这一节要先学这个能力"。
- 地图必须带**分组括号**（旧世界/新世界、端/网/远端）和**依赖方向**，否则读者不知道层次从哪看起；左侧标签要框住范围，只标在一层旁边会被误解成只指那一层。
- 给 2–3 套**正交分类维度**（位置/时间/可见性），让孩子给每个新词打标签：打不出标签＝没归类＝没真懂。
- 这张图是贯穿载体：每节课往里贴一片，结课时孩子手里是一张自己长出来的体系图，不是六个孤立作业。

## 三阶段骨架（UbD）
| 阶段 | 产出 | 检查问题 |
|---|---|---|
| 1 目标 | 学完能做什么（3–5 条）+ 核心问题（2–3 个） | 这些目标值得学吗？是否可检验？ |
| 2 证据 | 表现性任务 + 量规（3–4 档）+ 形成性检查点 | 什么证据能证明达到了？差一点的样子是什么？ |
| 3 活动 | 逐次课的教学流程（分钟级） | 活动是否直接指向证据？有没有只为热闹的环节？ |

## 每节课教案的最小结构
```
节次 / 时长 / 学段
学完能做（1–2 条，可检验）
关键概念（≤3 个）
流程：导入(5–10) → 讲解/示范(15–20) → 动手(40–60) → 分享反馈(15–20) → 收口(5)
教具清单（含备用方案）
学生产出物（可带走的实物/文档）
常见卡点 + 现场应对
分层：跟不上 / 已经很熟 各一条
形成性检查（怎么当场知道他们懂了）
```

## 学习科学检查项（命中越多越好）
- **检索练习**：讲完就小测/复述，不是"再讲一遍"（Dunlosky 2013 排前列的是 practice testing 与分散练习）
- **分散练习**：同一能力跨多次课复用，不靠一次猛灌
- **样例先行**：新手先看完整范例，再自己做（cognitive load / worked example）
- **减少无关负荷**：一页一个概念，术语首次出现就给一句话定义
- **及时反馈**：当场、具体、指向标准，而不是"不错"
- **迁移**：同一方法换情境再用一次（换题目/换学科/换工具）

## 项目式（PBL）合格线
真实问题 · 持续探究 · 学生有选择权 · 有公开产物 · 有反思 · 有量规。缺两项以上，就是"加了活动的讲授"。

## 交付前自检
- [ ] 目标可检验、证据能证明目标
- [ ] 每节都有学生动手与当场反馈
- [ ] 分钟级时间加总等于课时
- [ ] 术语、课时、排期、价格跨材料一致
- [ ] 学生材料（任务单/量规/反思卡）齐备，不只有教师稿
- [ ] 中文表述通顺，无英文直译腔（见 chinese-edu-copy）
- [ ] 需要“看懂原理”的环节，配一张**可操作的图**（见 interactive-courseware-visuals），不要用方块箭头图
- [ ] 学段用词/难度与教材对得上（见 `references/textbook-reference-library.md`）
