# 交互式可视化课件（把原理做成一合能动的机器）

## 何时用
- 要把一个**抽象概念**（分层、token、缓存、回路、传播）做成孩子能看懂、能动手的东西
- 要做课件里的“让学生拖一下/敲一下/拉开一层”的交互图
- 要替代“方框+箭头+标签”这种一放就困的静态图

## 铁律（违反任何一条就不是本 skill）
1. **物体即解释**：不画方块和箭头，为这个原理**发明一台真实机器**，它的运转本身就是概念。
   （例：缓存命中 = 弹子锁；共享 GPU = 龙门绘图仪；7 个不同字节的渲染目标 = 七个不同深度的抽屉。）
2. **每屏只讲一个概念**：一张图里出现两个机制，孩子一个也记不住。
3. **先真后画**：图上出现的每个数字（计数、阀值、比例）必须来自真实模型，不能编。
4. **必须有“发现感”**：画完要能回答——孩子捣鼓三下之后会“啊原来是这样”，说不出来就重做。
5. **两个失败方向**：太抽象（堆板子、浮块、带标签的盒子）与太平（一整块大板加几根线）——修法都是同一个：**一台能被认出来的机器，由很多小零件组成**。

## 五步管线
1. **定尺寸（先说清楚再做）**
   - Figure：40–80 个零件、单页 SVG、约 1 小时——默认就选这一档，不问直接做
   - Hero：80–150 个零件、可带 WebGL、2–4 小时——先报价再开工
   - Epic：整辆/整座、6 小时以上——**不擅自开工**，给估算并提 Hero 降级方案
2. **查真相**：真尺寸、真数量、真阀值、真曲线；能写成一个小纯模型模块（model.mjs）就用模型驱动全部动画与读数
3. **发明机器**：一句话说清“什么在动、这个动作意味着什么”（写不出来就是没想清）
4. **列零件清单**（≥40 个，分组：底座 / 结构 / 机制 / 控制 / 被解释的主体），每个零件都坐在另一个零件上
5. **建几何 → 从前到后排序 → 装框 → 做成可动 → 像批评家一样验收**

## 交付约束（我们的课，硬指标）
- **单文件 HTML**：零外部依赖、零 CDN，双击就能开（飞书发过去能直接看）
- **手机能看**：390 宽不横向溢出；触控能拖
- **体积 ≤ 5MB**；不用大图，全部矢量
- **静音与无障碍**：`prefers-reduced-motion` 下静止；键盘可操作（Tab 能选到控件）
- **中文标注**：只允许一个极小的入题标签，文字放到卡片下方，不塞在图里
- **卡片式装框**：Fig n 左上、短标题右上、操作提示左下、实时读数右下

## 验收清单（交付前逐条过）
- [ ] 1× 看：像一台真机器，不像示意图
- [ ] 4× 看：每个区域都有真细节，没有大面积空白与“未完成”的脸
- [ ] 每条线都终止在一条边/一点/一个轮廓上（没悬空线头）
- [ ] 没有穿模（零件不会互相穿过去）
- [ ] 动作用缓动/弹簧，不是硬切；静止时不抽搯
- [ ] 手机 390 宽不横向滑，触控能操作
- [ ] 弱动效下可用（不靠动画才能理解）
- [ ] 孩子捣鼓三下能得出那句结论

## 三个可复用图式（本课程已规划）
| 要讲的抽象 | 机器形态 | 交互 | 档位 |
|---|---|---|---|
| 输入—处理—输出 | 一台能敲字的机器：敲键→内部联动件→屏幕上出字；换三个外壳仍是同一套三段 | 敲、拉、换壳 | Figure |
| 消息路径（线+地址+规则） | 传送/分拣系统：贴地址、上路、落格；缺地址会卡住 | 拔掉地址块看卡在哪 | Figure |
| token 与计费 | 文字分拣计费机：句子进→切块→过称（token 数）→落价签 | 换句子看称重变化 | Figure |
| 五层知识地图 | 五层立式塔，每层抽屉可拉开；卸下层看上层还能不能转 | 拆层、装层 | Hero |

## 工具与资产（已装在本机）
- **Anatomy 技能套件**（MIT，`wheresryan22/anatomy`）：`~/tools/anatomy/`
  - 方法全文：`~/tools/anatomy/SKILL.md`（必读，含零件配方 `references/craft.md`、动效 `references/motion.md`、验收 `references/verify.md`）
  - 示例：`examples/desk-computer/`（可敲字、关机画面塔缩）、`examples/dial-indicator/`（最小示例~300 行）、`examples/arcade-cabinet/`（投币机构 + 管线）
  - 构建：`node build.mjs`（零依赖，出独立 HTML）；`node build.mjs --audit`（穿模/支撑/深度审计）；`node scripts/lines.mjs page.html`（线头检查）；`scripts/capture.mjs`（多尺寸截图）
  - 环境要求：Node ≥ 20.10（本机 v25 ✓）、Chrome（本机 ✓）
- 渲染校验：headless Chrome 截图 → 看图验收；清单表出 PDF 用 `--no-pdf-header-footer --print-to-pdf`

## 不要做
- 不要用 emoji、不要堆色块、不要“科技感渐变紫”
- 不要用大量文字说明代替一个能操作的图
- 不要复杂表格、线框流程图堆叠；能做成配对、翻牌、喂食、涂格子这类小游戏，就不要做成示意图+说明栏
- 不要把成人工程图的原样搬给孩子（零件数量与尺寸按 10–15 岁降级，但不能降到“只有三块板”）
- 主线活动不要被旁支拆开（例如三个怪问题中间不要插机房动画）
